# PHYSICS LAB: Last Ball Standing (MVP v1.0)

*Predict. Simulate. Survive.*

YouTube Shorts 向けの物理シミュレーション動画を **Matter.js（物理演算）** と **Remotion（描画・MP4書き出し）** で生成するプロジェクトです。
最初の企画は **Last Ball Standing**: 60個のボール（4色×15個）が回転するアリーナから脱落していき、最後に残った1個が勝者になる30秒の縦型動画です。

## セットアップ（Mac）

前提: Node.js 20 以上（推奨 22）、npm。 https://nodejs.org/

```bash
node -v && npm -v
cd physics-lab
npm install
```

初回の `npm run render` / `npm run dev` で、Remotion がレンダリング用の Chrome Headless Shell を自動でダウンロードします（ネットワーク接続が必要）。

## コマンド

| コマンド | 内容 |
| --- | --- |
| `npm run dev` | 既定seedをシミュレーションしてから Remotion Studio を起動（プレビュー） |
| `npm run render` | 既定seedで `out/last-ball-standing.mp4`（+ メタデータ `.json`）を書き出す |
| `npm run render -- --seed=42 --style=noir` | seed 42・noir スタイルで `out/last-ball-standing-42.mp4` を書き出す（`--out=パス` で出力先指定、`--force` で品質チェック不合格でも書き出す） |
| `npm run simulate -- --seed=42` | シミュレーションだけ実行し `public/simulations/lbs-42.json` を保存 |
| `npm run check -- --seed=42` | 品質チェック＋同じseedを2回実行して結果が一致するかを確認 |
| `npm run generate -- --count=3` | 簡易バッチ: 合格したseedを3本 `renders/` に書き出す（`--start-seed=N`、`--no-render`） |
| `npm run audio` | 効果音・BGMを再合成して `public/audio/` に書き出す |
| `npm run typecheck` | TypeScript の型チェック |

Studio で別のseedを見るには、先に `npm run simulate -- --seed=42` を実行し、Studio の Props で `seed` を `42` に変更します。

## デザイン（5パターン）

見た目は `style` で切り替える（物理・ルール・結果は同じ）。定義は `src/styles/presets.ts`。

| style | 内容 |
| --- | --- |
| `studio` | 白いスタジオ。つやのある4色の球、木の板、淡いブルーの金属 |
| `stairs`（既定） | らせん階段風。木の段板を放射状に並べた床、金属質の球 |
| `candy` | パステルのおもちゃ風。マットな球、やわらかい色 |
| `noir` | 黒い床にスポットライト。宝石・金属の球、真鍮のバー |
| `comic` | 黄色背景のコミック調。太い黒フチ、ベタ塗り、くっきりした影 |

```bash
npm run render -- --style=noir
```

Studio では Props の `style` を変更します。どのパターンでも、球は4色×6個で、上部カードに色ごとの残数を表示します。

## 仕組み: 物理演算と描画の分離

```
Matter.js（Node.js, 60Hz 固定ステップ）
  → 全ボールの座標・角度・ゲート・回転バーを毎ステップ記録
  → 動画900フレームへ時間マッピング（冒頭2秒の静止、勝者確定前後のスロー）
  → public/simulations/lbs-<seed>.json
Remotion
  → JSON を読み込んで各フレームを描画するだけ（物理演算は一切しない）
```

- 乱数はすべて seed 付き乱数（mulberry32）。同じ seed と設定からは同じ結果になる（`npm run check` で2回実行してハッシュ比較）
- seed が変わると、ボールの初期配置・色の割り当て・回転バーの腕の本数／速度／向き・バンパーの数／大きさ・ゲートの速度／向きが変わる
- 書き出し時のメタデータ（`.json`）に seed・設定・コース・勝者・脱落順・品質チェック結果・シミュレーションのハッシュ・ソースのコミットを保存

## ゲームモード（`--mode`）

| mode | 内容 | 球 |
| --- | --- | --- |
| `gate`（既定） | 回転する出口から外に出たら脱落（下記の詳細ルール） | 60個 |
| `collapse` | 真上から見た円形の床が、予告の点滅のあと1枚ずつ落ちる。落ちた床の上のボールは穴に落ちて脱落。床全体が傾き、傾きの向きがゆっくり回る。決着後は床が元に戻る | 48個 |
| `battle` | 全員HP20。敵チームにぶつけると（速いほうが攻撃側）1〜2ダメージ、中央の回転トゲは2ダメージ、4秒以降は縮んでいく外周の電気柵が1ダメージ。HP0ではじけて脱落。同じチーム同士はダメージなし（最後の1チームになったら同士討ちあり） | 24個 |

```bash
npm run render -- --mode=collapse --seed=20261036
npm run render -- --mode=battle --seed=20261035
```

### 後半のイベント（全モード共通の仕組み）

目標決着時刻の50%と78%の時点で、展開を変えるイベントが起きる（画面に大きなバナーと効果音）。

| mode | 1回目 | 2回目 |
| --- | --- | --- |
| `gate` | DOUBLE EXIT: 反対側にも出口が開く | SPEED UP: 出口と回転バーが2倍速 |
| `collapse` | EARTHQUAKE: 拍ごとに床が揺れ、傾きが強くなる（画面も揺れる） | SPEED UP: 傾きの回転と回転バーが2倍速 |
| `battle` | SUDDEN DEATH: 全ダメージ2倍・球が加速 | ZONE CLOSING: 電気柵が3秒で一気に縮む |

### テンポ

勝者確定は動画の約25〜27秒（結果表示は約3〜5秒）。序盤はゆっくり、後半に一気に減るように、残数の目標を (1 - 経過割合)^0.65 のカーブにしている。

どのモードも、テンポは「残数の目標カーブ」との差で自動調整（gate: 出口の開き幅、collapse: 床を落とす間隔とタイル選び、battle: ダメージ後の無敵時間とダメージ倍率）。期限までに決着しなければタイムアウトの規則で勝者を決める。

## ゲームルール（Last Ball Standing）

| 項目 | 内容 |
| --- | --- |
| アリーナ | 円形の壁。中央に回転バー（1〜3本の腕）とハブ、周囲にバンパー |
| 出口（ゲート） | 壁の一部が開いた出口が1つあり、壁に沿って回転する（時間とともに加速）。**出口は閉じない**。進行が速すぎるときは球より狭いすき間（通れない）まで絞るだけなので、出口の位置は常に見える（オレンジの帯と矢印） |
| 脱落 | ボールの中心がゲートを抜けて壁の外に出たら脱落。脱落ボールは壁の外側を転がって下の **OUT（ドロップゾーン）** に溜まる（画面から消えない） |
| 勝者 | 残り1個になった瞬間に確定。出口は最小幅に絞られ、勝者は壁の内側に保護される |
| 同時脱落 | 1物理ステップ（1/60秒）で脱落確定するのは最大1個。よって「全員同時に脱落して勝者なし」は起こらない |
| 衝撃波パルス | 4秒以降、BGMの拍（0.5秒）に合わせて中心から衝撃波が出て、生存ボールを外周へはじく（残り13個以上は1秒ごと、12個以下は0.5秒ごと） |
| 傾き | ゲート開始後、生存ボールにかかる重力の向きが左右に揺れる（周期2.4秒、最大40°、残り10個以下で70°）。底に溜まったボールが壁沿いに左右へ転がり続ける。中央の柱に重力の向きの矢印を表示 |
| 回転バー | 残り8個以下から徐々に加速（最大1.8倍） |
| タイムアウト | シミュレーション 24.5 秒（collapse は23.5秒）までに決着しなければ、**アリーナ中心に最も近いボールが勝者**。残りはその場で停止して脱落扱い（画面に TIME UP 表示） |
| テンポ調整 | 残数の目標カーブ（60 → 22秒で1）との差に応じて出口の開き幅を自動調整。目標時刻の3秒前を過ぎても残っていれば、時間とともにさらに大きく開く |

## 品質チェック（`src/pipeline/quality-check.ts`）

不合格（✘）の seed は `render` が中止し、`generate` は自動でスキップします。

- 900フレームあること / 全ボールが常に画面内で座標が有限
- 脱落数 = 23、勝者は脱落していない、残数は単調減少して最後は1
- タイムアウトではなく通常決着していること
- 勝者確定が動画の 18〜27 秒
- 勝者が決着後もアリーナ内にいること
- （警告のみ）最初の脱落が4秒以内 / 脱落の間隔が5秒以内

## 動画構成（30秒・1080×1920・30fps・H.264）

| 時間 | 内容 |
| --- | --- |
| 0〜2秒 | 「60 → 1」表示。ボールは静止 |
| 2秒〜 | GO! でスタート。上部カードに残数と色ごとの残数、脱落時に波紋＋効果音 |
| 残り3個以下 | 周辺減光、「FINAL n」表示 |
| 勝者確定の約1秒前〜直後 | 0.35倍スロー＋ズーム |
| 確定後（概ね 21〜26秒〜） | フラッシュ、勝者スポットライト、紙吹雪、WINNER カード |

## MVPとしての判断・既知の制約

- **全ボール・全フレームの座標を JSON に保存**（1本あたり約0.5MB）。`public/simulations/` は生成物なので git 管理外
- **脱落はまとまって起きやすい**: 出口が底の球だまりを通過するたびに十数個まとめて落ちる「波」になる。展開の演出として許容し、5秒超の空白は警告扱い
- **最後の2個がほぼ同時にゲートを抜けた場合**、残る1個（勝者）が壁の内側へ引き戻され、一瞬位置が飛ぶことがある。品質チェック「勝者は決着後もアリーナ内」で検出して不採用にする（一部の seed で発生。例: seed 501）
- タイムアウト決着の seed は品質チェックで不採用（ルールとしては実装済み）
- ボール数60個・半径14pxで調整済み。数を変える場合はテンポ調整・パルス・傾きの再調整が必要
- 3D化・YouTube自動投稿・大規模バッチは後続フェーズ
